RAG 평가⁠·​운영 지표

자동 테스트 수, 검색 성능, 실제 답변 품질, 운영 시간을 나누어 확인합니다.

공개된 기본 보고서는 가짜 LLM을 이용한 오프라인 평가 도구 검증 결과입니다. 실제 서비스 성능을 뜻하지 않습니다.

기존 평가 도구와 고정 질문

평가 코드⁠·​고정 질문 원본 ↗ · 실제 모델용 질문 9개 내려받기 · 오프라인 보고서 원본

국보 저장소에서 수집⁠·​색인과 모델 설정을 마친 뒤 다음 명령으로 같은 질문을 반복 평가합니다. API 키는 로컬 환경 변수에만 설정합니다.

python -m evals.run --configs similarity:4,mmr:4,similarity:8

생성된 docs/eval_report.json을 아래에 올려 비교하세요. 설정을 고르는 개발용 질문과 최종 검증용 질문은 분리하고, 모델⁠·​프롬프트⁠·​데이터 버전과 실행 환경을 함께 기록하세요.

설정별 결과

검색 재현율과 필수 사실 포함률은 고정 질문에 지정된 문자열 기준입니다. 인용 정밀도는 번호의 존재 여부이며 의미 일치를 보장하지 않습니다. 근거 겹침은 2-gram 휴리스틱으로 사람 검토 대상 선정용입니다.

근거 의미 일치 직접 검토

보고서의 겹침이 낮은 문장을 확인한 뒤, 원문을 열어 실제로 주장 전체를 뒷받침하는지 판정하세요. 일부 문장만 확인했다면 전체 답변 품질로 일반화하지 않습니다.

내 실행 기록으로 운영 지표 계산

실제 실행마다 한 줄씩 기록한 JSONL을 올리세요. 이 페이지에서만 계산하며 서버로 보내지 않습니다. 실패한 실행도 포함해야 성공률을 해석할 수 있습니다. 실행 시간에는 어떤 단계를 포함했는지 별도로 기록하세요.

{"id":"run-001","status":"success","elapsedMs":1250,"retries":0,"costUSD":null,"freshnessMs":null}

실제 운영 기록 미등록

아직 별도 측정이 필요한 운영 지표

  • 한끼 Agent: 실제 키로 대표 시나리오를 다시 돌려 요청별 지연 시간⁠·​실패율⁠·​재계획 횟수 기록
  • 데이터 웨어하우스: 예정 실행 대비 성공률, 최신 데이터 지연, 실패 후 복구 시간 기록
  • 실제 RAG: 질문별 총 시간의 평균⁠·​p95, 모델/API 청구 사용량, 검색 및 답변 오류율 기록

측정하지 않은 처리량⁠·​비용⁠·​성공률은 수치로 표시하지 않습니다. 테스트 개수는 운영 성능과 구분합니다.
