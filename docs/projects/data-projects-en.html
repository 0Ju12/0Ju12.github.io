Problem

I needed examples on real data from my target fields (resource development, energy, manufacturing IT, finance) that go from collection to validation, and the joint-research data cannot be published

My role

Build projects that run repeatedly like production work and are evaluated honestly, using only data anyone can download

What I did

  1. Earthquake pipeline: incremental collection from the USGS FDSN API with per-region minimum magnitude and start date (re-fetching the last 3 days so runs are idempotent); only newer revisions replace an event; events without magnitude, out of range or non-earthquake are quarantined and counted; CSV (source) and SQLite (query) storage; Mc and b-value (Aki–Utsu, Shi & Bolt error); a Leaflet dashboard refreshed daily by GitHub Actions
  2. Equipment anomaly detection: 136 cycle features from 2,205 cycles × 17 sensors of the UCI hydraulic rig; per-component normal models (Ledoit-Wolf Mahalanobis, 1% false-alarm threshold) with a k-consecutive alert rule; RandomForest vs LDA diagnosis under random and time-block splits
  3. Power demand forecasting: day-ahead 24-hour forecasts from KPX 2025 national hourly demand and Open-Meteo temperature — features use only values at least 24 hours old (with a leakage test), holidays included; baseline, linear, GBM and ensemble tested on October–December
  4. DART data mart: OpenDART collection (status-code handling, rate-limit waits), standardised accounts, pivot/LAG/RANK SQL views, and evidence search over business-report paragraphs with character-bigram BM25, returned with sources (API key only via Secrets)

Results

  • Power demand: MAPE 6.17% for the same-hour-last-week baseline → 3.23% for the ensemble; daily-peak error 2.64%
  • Sensor diagnosis: RandomForest scored 0.99+ on every component with a random split but 0.46 on the valve with a time-block split; LDA kept 1.00 on cooler, valve and pump, while the accumulator (0.55) remains open
  • Earthquakes: 2,446 events of M4+ in East Asia, b = 1.11 ± 0.05 · 35 tests across the four projects

Decisions & trade-offs

What I chose, and what I gave up for it

Evaluation split: in time series where neighbouring points are nearly identical, random splits inflate scores, so both the sensor diagnosis and the demand forecast default to time-ordered splits (train on the past, test on the future), with random-split results reported alongside.
Earthquake storage: a human-readable, diff-able CSV is the source of truth and SQLite is rebuilt for queries — slightly larger files, but every change stays visible in the repository history.
DART evidence search returns source paragraphs instead of generated answers — less fluent, but no risk of a wrong summary.

Looking back · open questions

What I would change, and what is still open

Accumulator diagnosis (0.55) seems to need features such as the time constant of pressure build-up more than a different model.
Only one year of demand data is public, so no season is seen twice; I plan to re-evaluate with several years and real temperature forecasts.
