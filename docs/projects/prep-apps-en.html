Problem

SSAFY lecture notes, interview answers and cover letters cannot go into a public repository, yet I needed to review and practise on my phone while on the move — without running a server

My role

Deploy the content encrypted using only static hosting (GitHub Pages), so that only someone with the password can open it in the browser

What I did

  1. Encryption: at build time each page is sealed with AES-GCM under a key derived by PBKDF2-SHA256 (600k iterations) and decrypted with the browser's Web Crypto; one key per build, so a single unlock per tab opens both apps. Builds without a password emit empty lock pages only
  2. Study app: titles, outlines and summaries extracted from 52 notes; 957 practice questions (multiple choice, cloze, written), keyword cards, weakness report and mock exams; the full-text index is gzipped and encrypted with the same key; spaced review at 1·3·7·14·30 days
  3. Interview app: question bank with typical vs strong answers, answer skeletons and decks generated from portfolio data (presenter mode; PDF/PPTX built in the unlocked browser), timed/recorded mock interviews, an OPIc practice set, recruiting info for 38 organisations, 30 cover-letter prompts with core-experience balancing, goal D-days and weekly checks
  4. Operation: the scheduled job adds new questions as public-key-sealed add-on files without the private key and the deploy build merges them; math fonts moved to one shared file to cut note size by more than half; progress moves between devices as password-protected files that merge rather than overwrite

Results

  • Runs on GitHub Pages with no server and leaves no plaintext in the repository or the deployment · moving math fonts to a shared file cut encrypted notes from about 44 MB to 20 MB
  • Bottom tab bar on phones and offline install (PWA); main desktop and phone flows pass automated checks

Decisions & trade-offs

What I chose, and what I gave up for it

Build-time encryption with in-browser decryption instead of a server and logins: no accounts or hosting cost, but one password opens everything and changing it means rebuilding. PBKDF2 at 600k iterations raises the cost of guessing.
Progress lives only in the browser: nothing personal goes to a server, but there is no automatic cross-device sync, so password-protected files move it and merge rather than overwrite (more practice wins; the later memo wins).
PDF and PPTX are generated in the unlocked browser rather than pre-built: a short wait on click, but no plaintext file downloadable without the password is left in the deployment.

Looking back · open questions

What I would change, and what is still open

Automatic sync across devices needs a small store for end-to-end encrypted progress — currently only file transfer is implemented.
Speech-to-text on OPIc recordings to show answer length and repeated phrases.
