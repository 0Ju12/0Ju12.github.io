문제

지원 분야(자원개발·에너지·제조 IT·금융)의 실제 데이터로 수집부터 검증까지 해 본 사례가 필요했고, 공동연구 데이터는 공개할 수 없었음

역할

누구나 받을 수 있는 공개 데이터만으로, 실무처럼 반복 실행되고 정직하게 평가된 프로젝트를 만드는 것이 목표

한 일

  1. 지진 데이터 파이프라인: USGS FDSN API 를 지역별 최소 규모·시작일로 증분 수집(마지막 실행 3일 전부터 겹쳐 받아 멱등), 같은 id 는 더 늦은 수정본만 교체, 규모 없음·범위 밖·발파는 격리해 개수만 보고, CSV(원본)·SQLite(질의용) 저장, Mc·b값(Aki–Utsu, Shi & Bolt 오차) 분석, Leaflet 지도 대시보드를 매일 GitHub Actions 로 갱신
  2. 설비 센서 이상 탐지: UCI 유압 설비 2,205 사이클 × 17 센서에서 사이클 특징 136개 추출, 부품별 정상 모델(Ledoit-Wolf 마할라노비스, 1% 오경보 임계값)과 k 연속 경보 규칙, RandomForest·LDA 진단을 무작위 분할과 시간 구간 분할로 비교
  3. 전력 수요 예측: 전력거래소 2025년 시간별 전국 수요와 Open-Meteo 기온으로 하루 전 24시간 예측 — 24시간 이상 지난 값만 쓰도록 특징을 만들고(누수 검사 테스트), 공휴일·연휴를 반영해 기준선·선형·GBM·앙상블을 10~12월로 시험
  4. DART 데이터 마트: OpenDART 수집(오류 코드별 처리·한도 대기), 표준 계정 정규화, 피벗·LAG·RANK SQL 뷰, 사업보고서 문단을 글자 2-gram BM25 로 찾아 출처와 함께 보여 주는 근거 검색 (인증키는 Secrets 로만)
  5. 웨어하우스: 지진·수요·기온 원본을 dbt(DuckDB)로 staging → intermediate → marts 3단 모델링 — 날짜 × 24열 수요표를 시간별 행으로 풀면서 '24시'를 다음 날로 넘기지 않도록 시작 시각을 키로 삼고, USGS 가 고친 지진은 덮어쓰지 않고 이력(SCD 2형)으로 쌓음. 같은 함수를 Airflow DAG·명령줄·테스트가 함께 쓰고, 날짜 파티션 내보내기는 다시 돌려도 같은 파일이 나오게 함

결과

  • 전력 수요: 지난주 같은 시각 기준선 MAPE 6.17% → 앙상블 3.23%, 일 최대수요 오차 2.64%
  • 센서 진단: 무작위 분할에서 모든 부품 0.99 이상이던 RandomForest 가 시간 구간 분할에서 밸브 0.46 — LDA 는 냉각기·밸브·펌프 1.00 유지, 축압기 0.55 로 남은 과제 확인
  • 지진: 동아시아 M4+ 2,446건, b = 1.11 ± 0.05 · 테스트 35개(4개 프로젝트 합계)
  • 웨어하우스: 모델 10개 · 품질 테스트 36개(범위·관계·하루 24행·집계 대조) 통과, 잘못된 자료를 넣으면 빌드가 실패하는 것과 증분 집계가 전체 재계산과 같은 것까지 pytest 19개로 확인 · Airflow 는 DAG 1회 실행까지만 확인(상시 운영은 아님)

설계 판단 · 트레이드오프

무엇을 고르고, 그 대신 무엇을 포기했는지

평가 분할: 이웃한 시점이 거의 같은 시계열에서 무작위 분할은 성능을 부풀림 → 센서 진단과 수요 예측 모두 '과거로 학습해 미래를 시험'하는 시간 분할을 기본으로 하고, 무작위 분할 결과를 옆에 같이 보고
지진 파이프라인 저장: 사람이 읽고 diff 할 수 있는 CSV 를 원본으로, SQLite 는 매번 다시 만드는 질의용으로 — 파일은 조금 커지지만 변경 이력이 저장소에 그대로 남음
DART 근거 검색: 생성형 답변 대신 원문 문단과 출처만 돌려줌 — 문장이 매끄럽지 않은 대신 틀린 요약을 만들 위험이 없음
