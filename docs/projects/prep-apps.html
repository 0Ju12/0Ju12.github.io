문제

SSAFY 강의 노트와 면접 답변·자소서는 공개 저장소에 올릴 수 없지만, 이동 중에도 휴대폰으로 복습하고 면접을 연습할 수 있어야 했고, 서버를 따로 운영하고 싶지 않았음

역할

정적 호스팅(GitHub Pages)만으로 내용은 암호화된 채 배포하고, 암호를 아는 사람만 브라우저에서 풀어 쓰는 앱을 만드는 것이 목표

한 일

  1. 암호화: 빌드에서 페이지마다 PBKDF2-SHA256(60만 회)로 만든 키와 AES-GCM으로 본문을 잠그고, 브라우저 Web Crypto로 풂 — 같은 빌드는 한 키를 써서 한 번 연 탭에서는 학습·면접 앱 모두 다시 묻지 않음. 암호가 없는 로컬 빌드는 내용 없는 잠금 페이지만 만듦
  2. 학습 앱: 노트 52편에서 제목·목차·요약을 뽑고 확인 문제 957개(객관식·빈칸·서술)·키워드 카드·약점 리포트·모의고사를 생성, 본문 검색 색인은 gzip 후 같은 키로 암호화, 1·3·7·14·30일 간격 복습
  3. 면접 앱: 예상·합격 답변 질문 은행, 포트폴리오 데이터로 만든 프로젝트별 답변 뼈대와 발표 자료(발표자 모드, PDF·PPTX를 잠금을 푼 브라우저에서 생성), 타이머·녹음 모의 면접, OPIc 실전 세트, 공채 정보 38곳, 자소서 30문항·핵심 경험 배분, 목표 D-day·주간 체크
  4. 운영: 정기 작업은 개인키 없이 새 면접 질문을 공개키로 잠근 추가 파일로만 올리고 배포 빌드가 합침, 수식 폰트를 공용 파일로 분리해 노트 용량을 절반 이하로, 기기 간 기록은 암호를 건 파일로 옮겨 합침(덮어쓰지 않음)

결과

  • 서버 없이 GitHub Pages에서 운영하면서 저장소와 배포본 어디에도 평문을 남기지 않음 · 수식 폰트 분리로 암호화된 노트 용량 약 44MB → 20MB
  • 휴대폰 하단 탭·오프라인 설치(PWA)까지 지원, 데스크톱·휴대폰 주요 흐름 자동 점검 통과

설계 판단 · 트레이드오프

무엇을 고르고, 그 대신 무엇을 포기했는지

서버·로그인 대신 빌드 시 암호화 + 브라우저 복호화: 계정 관리·서버 비용이 없지만, 암호 하나로 전체를 여는 구조라 암호를 바꾸면 다시 빌드해야 함. 반복 횟수(PBKDF2 60만 회)로 추측 공격 비용을 높임
기록은 브라우저에만 저장: 개인정보가 서버로 가지 않는 대신 기기 간 자동 동기화는 없음 → 암호를 건 파일로 옮겨 '덮어쓰기'가 아닌 '합치기'(연습 횟수가 많은 쪽, 나중에 고친 메모 우선)로 보완
PDF·PPTX는 서버에 미리 만들지 않고 잠금을 푼 브라우저에서 생성: 버튼을 누를 때 조금 기다리지만, 암호 없이 받을 수 있는 평문 파일이 배포본에 남지 않음
