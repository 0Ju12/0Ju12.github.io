한눈에 보기

1한 곳만 고치면 국문·영문 사이트·이력서·프로젝트 상세 14쪽이 함께 바뀜
2배포마다 전체 페이지(90쪽 이상) 링크 점검 · 주요 페이지 데스크톱·휴대폰 화면 점검
31쪽 이력서가 1쪽을 넘으면 빌드에서 바로 확인

문제

이력서(1장·상세·직무별·영문), 웹 포트폴리오, 노션, LinkedIn에 같은 경험을 따로 쓰다 보니 수치·표현이 조금씩 달라지고, 고칠 때마다 여러 곳을 손봐야 했음

역할

사실은 한 곳에만 두고 나머지는 모두 거기서 만들어지게 해, 내용이 서로 어긋나지 않고 배포 전에 깨진 곳을 기계가 잡게 하는 것이 목표

한 일

  1. 데이터: data/portfolio.yaml(국문)·portfolio.en.yaml(영문)에 활동·프로젝트를 STAR 구조로 저장, 프로젝트별 설계 판단·회고는 case_notes.yaml로 분리
  2. 빌드: Python + Jinja2로 메인 페이지, 프로젝트 상세(국·영 14쪽), 이력서(1장·상세·데이터/AI 직무별·영문)와 PDF 5종(Playwright 인쇄), 검색 색인, 프로젝트별 공유 이미지·sitemap, 노션·LinkedIn 문구를 한 번에 생성
  3. 점검: 필수 항목·링크 누락 경고를 --strict로 빌드 실패 처리, 배포 전 전체 페이지 링크 점검과 주요 페이지의 데스크톱·휴대폰 화면 점검(가로 넘침·겹침) 자동 실행
  4. 비공개 자료: 연락처·증빙·면접 답변 원문은 공개키(RSA-OAEP + AES-GCM)로 잠근 파일만 커밋하고, GitHub Actions가 비밀 키로 풀어 암호화 페이지로만 출력 — 평문은 저장소에 남지 않음
  5. 부가 기능: LLM 없이 사이트 글에서 문단을 찾아 출처와 함께 보여 주는 '포트폴리오에 질문하기', RAG 근거 번호 검증 미니 데모, 연구 지역 커리어 지도(Natural Earth), AI 트렌드 연재 글 목록

결과

  • 한 곳만 고치면 국문·영문 사이트·이력서 PDF·프로젝트 상세가 함께 바뀌어, 수상명 영문 표기 같은 오류도 한 번에 바로잡을 수 있음
  • 배포마다 전체 페이지(90쪽 이상) 링크 점검과 데스크톱·휴대폰 화면 점검을 통과해야 배포

설계 판단 · 트레이드오프

무엇을 고르고, 그 대신 무엇을 포기했는지

프레임워크(Next.js 등) 대신 Python + Jinja2 정적 생성: 화려한 기능은 줄지만, 데이터(YAML)와 화면을 분리해 같은 데이터로 사이트·이력서 PDF·노션 문구를 함께 만들 수 있고 빌드가 단순해짐
점검을 사람이 아닌 빌드에 맡김: 배포가 조금 느려지는 대신 깨진 링크·필수 항목 누락·휴대폰 가로 넘침·1쪽 이력서 넘침을 배포 전에 잡음
비공개 자료는 공개키로만 잠가 커밋: 정기 작업도 개인키 없이 자료를 추가할 수 있지만, 푸는 것은 비밀 키가 있는 배포 빌드에서만 가능

돌아보면 · 남은 과제

다시 한다면 바꿀 것, 아직 남은 것

방문 통계(GoatCounter)를 연결해 어떤 프로젝트·이력서가 실제로 읽히는지 보고 순서를 정하는 것
영문 페이지는 국문 데이터를 따로 번역해 관리하고 있어, 항목 누락을 자동으로 비교하는 점검을 추가할 계획
