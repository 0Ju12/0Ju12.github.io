AI 트렌드 노트

AI 에이전트의 기본 개념부터 시작해, 하루 두 편씩 이어서 정리하는 기술 노트입니다. 편마다 최근 동향(출처 포함), 동작 구조, 한계, 그리고 제가 만든 프로젝트와의 연결을 적습니다.

#8 · 멀티 에이전트 오케스트레이션 — 나누면 빨라지지만 맥락이 끊긴다2026-11-12 · 일을 여러 에이전트에게 나눠 맡기는 구조(지휘자-작업자, 핸드오프)의 장단점을 정리했습니다. 병렬 조사에서는 효과가 보고됐지만 토큰이 크게 늘고, 맥락이 쪼개져 생기는 실패가 따로 연구될 만큼 흔합니다.#7 · RAG에서 Agentic RAG로 — 검색을 한 번 할지, 에이전트가 여러 번 할지2026-11-12 · 한 번 검색해 답하는 RAG와, 검색 여부·횟수·결과 품질을 스스로 판단하는 Agentic RAG의 차이를 정리했습니다. Self-RAG·CRAG·Adaptive-RAG가 각각 어느 판단을 추가했는지와, 반복이 늘 때 생기는 비용과 평가 문제를 봅니다.#6 · 에이전트 메모리 — 대화가 끝나도 남는 것과 남기면 안 되는 것2026-11-11 · 컨텍스트 창 안의 단기 기억과 대화 밖에 저장하는 장기 기억을 나누고, 무엇을 쓰고 언제 꺼내는지의 설계를 정리했습니다. 한 번 오염되면 세션이 끝나도 남는 메모리 포이즈닝도 함께 봅니다.#5 · ReAct와 Plan-and-Execute — 에이전트는 어떻게 계획하나2026-11-11 · 한 걸음마다 다시 생각하는 ReAct와, 먼저 계획을 세우고 실행하는 Plan-and-Execute의 차이를 비용·속도·실패 방식으로 비교했습니다. ReWOO·LLMCompiler 같은 변형과 코딩 에이전트의 plan mode까지 이어서 봅니다.#4 · 에이전트 간 통신 — A2A는 MCP와 무엇이 다른가2026-11-10 · MCP가 '에이전트와 도구'를 잇는다면 A2A는 '에이전트와 에이전트'를 잇습니다. Agent Card로 상대를 찾고, 상태가 있는 task로 일을 맡기는 구조와, 버전마다 바뀐 부분·엇갈리는 보도를 정리했습니다.#3 · MCP — 도구를 매번 새로 붙이지 않는 방법2026-11-10 · 지난 회차의 tool use를 앱마다 다시 만들지 않도록 '도구 서버'를 표준 규격으로 분리한 MCP의 구조(호스트·클라이언트·서버, tools·resources·prompts)와 최근 사양 변화, 보안상 약한 고리를 정리했습니다.#2 · Tool use — 모델은 함수를 실행하지 않는다2026-11-09 · Function calling의 실제 동작(모델은 호출 '요청'만 만들고 실행은 내 코드가 한다), strict 스키마와 Structured Outputs의 관계, 도구를 쓸 때와 출력 형식만 고정할 때를 구분했습니다.#1 · AI 에이전트란 무엇인가 — LLM이 도구를 쥐고 반복할 때2026-11-09 · 에이전트를 '도구를 쓰며 스스로 다음 단계를 정하는 LLM 루프'로 정의하고, 워크플로와 무엇이 다른지, 기업 도입 숫자가 왜 엇갈리는지 정리했습니다.
