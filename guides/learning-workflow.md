# 알고리즘 기록과 공개 포트폴리오

## 입력 일괄 등록

알고리즘 기록의 `입력·출력 TXT / ZIP 일괄 등록`을 열어 파일을 선택한다. `2001_input.txt`, `2001/input.txt`처럼 번호가 있으면 후보를 지정한다. 번호가 없거나 여러 개면 문제 번호를 직접 입력한다. 입력/예상 출력을 구분하고 `검토한 파일 적용`을 누른다. 같은 문제·종류의 중복은 하나만 선택한다. 기본적으로 기존 값은 유지하고, 교체를 허용하면 이전 코드·입력을 버전으로 남긴다. 일괄 등록은 기기에만 저장하며 Drive/GitHub 저장은 해당 문제의 기록 저장을 눌러 수행한다. SWEA 로그인이 필요한 공식 파일을 우회 다운로드하지 않는다.

최대 파일 100개, ZIP 12MB, 개별 압축 해제 1MB, 압축 해제 총량 10MB, 텍스트 총량 100만 자. ZIP은 일반 UTF-8 파일명과 stored/deflate를 지원한다. 지원하지 않는 파일명·브라우저에서는 압축을 풀어 TXT를 선택한다.

## 출력과 비교 실행

예상 출력이 있으면 기존 공백 정규화 정책(CR 제거, 줄 끝 공백 및 전체 앞뒤 공백 무시)에 따라 첫 불일치 줄과 Unicode 문자 위치를 표시한다. 테스트별 출력에서도 확인한다. 같은 입력 비교는 별도 Worker에서 A/B 코드를 각각 실행한다. 편집기 코드를 변경하지 않는다. 추적 한도는 각각 6천 단계/12MB, 60초다. 시간은 Python 로딩·추적 비용이 포함되어 온라인 채점 성능으로 쓸 수 없다. 예제는 양의 정수 부분집합 합이며 `visits` 변수로 가지치기 효과를 본다.

## 강의 연결과 회고

문제별 노트 선택에서 절 제목을 누르면 잠금을 해제한 뒤 그 절로 이동한다. `learn-section-N` 앵커는 암호화된 노트 안에 생성되며 원래 heading id는 보존한다. 회고 Markdown은 현재 코드·입력·출력·메모·오답 원인과 관찰 통계를 포함하며 공개 전 직접 검토한다. 시간·공간 복잡도는 사용자가 근거와 함께 작성한다.

## 공개 체험과 평가

`learning-demo.html`은 예제만 사용하고 저장소 인증·개인 기록을 읽지 않는다. `ephemeral=1` 모드에서 편집기 로컬 저장을 하지 않는다. `evaluation.html`의 기본 RAG 보고서는 heritage-rag-guide의 가짜 LLM 결과다. 실제 모델 품질로 해석하지 않는다. 같은 저장소에서 `python -m evals.run --configs similarity:4,mmr:4,similarity:8`을 실행한 JSON을 가져와 비교하고, 모델·프롬프트·데이터 버전, 실제 비용(모르면 공란), 사람 검토를 함께 내보낸다. 번호 검증·문자열 적중·2-gram 겹침과 의미 일치 검토는 별도다.

운영 JSONL은 실행 ID, success/failure, elapsedMs를 필수로 하고 retries/costUSD/freshnessMs를 선택으로 받는다. 실패한 실행도 포함한다. 성공률·평균·p95·재시도와 확인된 비용만 계산하며 미측정 비용을 0으로 바꾸지 않는다. 문서 내 예시 숫자는 입력 형식 예시이며 실제 성과가 아니다.
